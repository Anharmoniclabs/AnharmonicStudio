# Design, music, and audio research library

Research checked 2026-09-05. Book metadata, public descriptions, contents, and available author pages were consulted; this is not a claim that all books were read. Links to commercial titles are reading recommendations, not purchases. The application and evidence columns below are our project-specific design judgments.

For paywalled books, use available contents to choose a topic, then obtain a legitimate excerpt or a public author paper before attributing a specific technique. Do not download unauthorized book copies or copy commercial code/art into this project.

## DAW workflows and Linux engineering references

| Primary source | Why it matters here |
|---|---|
| [Ardour manual: signal routing](https://manual.ardour.org/signal-routing/) | A practical Linux DAW reference for explaining and testing track, bus, input, and output relationships. Study the workflow, then design for this studio's own model. |
| [Ableton manual: automation and editing envelopes](https://www.ableton.com/en/manual/automation-and-editing-envelopes/) | Compare manual adjustment, automation state, editing, and recording interactions when extending the existing gain/pan lanes. |
| [JACK API: client callbacks](https://jackaudio.org/api/group__ClientCallbacks.html) | Documents restrictions on blocking and allocation in process callbacks. Use it to review real-time boundaries, not to claim that using native kernels alone makes the engine real-time safe. |
| [PipeWire properties](https://docs.pipewire.org/page_man_pipewire-props_7.html) | Distinguishes requested latency/rate from graph behavior. Recheck the installed version before API or integration changes; do not force the user's graph settings. |
| [LV2 specification overview](https://lv2plug.in/pages/why-lv2.html) and [core API](https://lv2plug.in/c/html/group__lv2core.html) | Control units, feature negotiation, state, and non-real-time worker facilities inform a proper Linux plugin-host design. |
| [CLAP's official repository](https://github.com/free-audio/clap) | Consult current headers and extensions when evaluating events, expressive control, threading, state, and plugin lifecycle. No hosting support is implied by listing this reference. |

For a new task, record: the musician's problem → source passage/API and URL → your interpretation → smallest coherent implementation → acceptance evidence → remaining uncertainty. Keep the record in `MEMORY.md` or a focused design note. Research should resolve a concrete decision; do not reread the entire bibliography every hour.

Agent execution uses the installed Codex CLI and a Linux user timer. [OpenAI's non-interactive-mode documentation](https://learn.chatgpt.com/docs/non-interactive-mode) documents scheduled/scripted `codex exec`, explicit sandboxing, structured results, and existing CLI authentication. The local CLI help was checked against that guidance. This setup does not depend on an unexposed desktop scheduling API.
